# REQ-001: Calculation Processing Requirements

## Business Objective

The Calculation Service shall provide reliable arithmetic operations while
ensuring input validation, calculation traceability, and predictable failure
handling.

## Functional Requirements

### FR-001: Addition

The system shall support addition of two numeric values.

### FR-002: Subtraction

The system shall support subtraction of two numeric values.

### FR-003: Multiplication

The system shall support multiplication of two numeric values.

### FR-004: Division

The system shall support division of two numeric values.

Division by zero shall not be permitted.

A division-by-zero attempt must raise a controlled domain exception.

## Validation Requirements

### VR-001

All arithmetic operations must validate their input values before performing
the calculation.

Only integer and floating-point numeric values are supported.

### VR-002

The absolute value of an input must not exceed 1,000,000.

An unsupported value must be rejected before the calculation is performed.

## History Requirements

### HR-001

Every successfully completed calculation must be recorded through
HistoryService.

The history record must contain:

- operation type
- first input
- second input
- calculated result
- timestamp

Failed calculations must not be recorded as successful calculation history.

## Audit Requirements

### AR-001

Every successfully completed operation must generate a SUCCESS audit event.

### AR-002

A division-by-zero attempt must generate a FAILURE audit event.

The audit event must contain sufficient information to identify the failed
operation.

## Architectural Constraints

### AC-001

Calculator is responsible for orchestrating calculation operations.

Input validation must remain delegated to InputValidator.

Calculation history must remain delegated to HistoryService.

Audit recording must remain delegated to AuditService.

### AC-002

Arithmetic operations must not bypass InputValidator.

### AC-003

Successful calculations must not return a result before HistoryService and
AuditService have processed the calculation.

## Reliability Requirement

### RR-001

A change affecting Calculator, InputValidator, HistoryService, or AuditService
must be evaluated for impact on dependent calculation flows before production
deployment.
